# Gyroship practice file, ready for the game's update that Gyroship targets: main's build ID
# a7730d0f74d168d90422354c8317f76ff78ad938 (gyroship-tools nso info <exefs>/main prints yours).
# With that build, use it as it is, once the game is recompiled with templates/probes.txt:
#   gyroship boot <exefs> --play --explore --practice templates/practice.txt --boost perfect --hud
# or give its full path, <repository>/templates/practice.txt, in the launcher's Practice file
# field. Another build has other addresses and offsets: docs/practice.md says how to find them.
#
# Rules
# - One action per line. A comment is a whole line that starts with #: never put one after a
#   line's words.
# - The second word of a boost, hud-speed, ms-keep or ms line is the address, in hex without 0x,
#   of a trace: probe compiled into the game (probes.txt). The probe runs before the instruction
#   at that address.
# - An item's EXPR is a register xN (x31 is SP), a hex number written with 0x, or [EXPR], the
#   64-bit value stored at that address; then any number of +0xHEX or -0xHEX offsets. For example
#   f32@[[x0]+0x8]+0x4: read the pointer at x0, then the pointer 8 bytes past it, then the float 4
#   bytes past that.
# - A bad line stops the start with exit code 2 and names the line (font lines are read only with
#   an overlay). The start does not check where a field points: --boost infinite writes wherever
#   gauge and lock point.

# Boost (--boost, and the vehicle whose markers --hud-markers draws), at the first instruction of
# each vehicle's per-frame boost update. Fields:
#   gauge (f32)      the boost meter, a heat: 0 is a full bar
#   lock (u8)        set while boost and brake are refused, until the meter is back to 0
#   speed (f32)      the boost speed, added to the vehicle's base speed
#   boosting (u8)    set while boosting
#   warp accel decel max brake brake_recover brake_floor gauge_max fill drain (f32)
#                    the ten settings, as the running boost script holds them
# --boost infinite needs gauge and lock. --boost perfect needs all 14 on the Arwing's and the
# Blue-Marine's lines, and acts only while the ten settings read the values of
# crates/research/src/boost.rs; so do their markers. The Landmaster needs gauge and lock only.
# Arwing, Blue-Marine, Landmaster:
boost 7108e5d8f0 arwing gauge=f32@[[[[x0]+0x18]+0x38]]+0xa0 lock=u8@[[[[x0]+0x18]+0x38]]+0xd3 speed=f32@[[[[x0]+0x18]+0x38]]+0x9c boosting=u8@[[[[x0]+0x18]+0x38]]+0xd0 warp=f32@[[[x0]+0x18]+0x30]+0x0 accel=f32@[[[x0]+0x18]+0x30]+0x18 decel=f32@[[[x0]+0x18]+0x30]+0x30 max=f32@[[[x0]+0x18]+0x30]+0x48 brake=f32@[[[x0]+0x18]+0x30]+0x60 brake_recover=f32@[[[x0]+0x18]+0x30]+0x78 brake_floor=f32@[[[x0]+0x18]+0x30]+0x90 gauge_max=f32@[[[x0]+0x18]+0x30]+0xa8 fill=f32@[[[x0]+0x18]+0x30]+0xc0 drain=f32@[[[x0]+0x18]+0x30]+0xd8

# Level time to the millisecond, active whenever these lines are here. ms-keep: where the game is
# about to format a level time, its milliseconds in register wN. ms: right after the game's
# integer formatter returned that time's two-digit seconds, xN holding the string value it
# returned; "SS" then becomes "SS.mmm", written in place with no check that there is room: 4 bytes
# past the end of the "SS" string. Point ms only at the value the formatter has just returned,
# never at a later copy of the seconds, which the game sizes exactly. First the results screen
# (ms-keep, ms), then the game's
# own mission timer, shown when a game setting is switched on by a layer (its time string's two
# entries, then the seconds inside its minutes-and-seconds formatter). Lines are not paired by
# their order: a game thread's ms pass takes the milliseconds its last ms-keep pass kept.
