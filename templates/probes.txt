# Gyroship probe list: a template, for the practice file (practice.txt, next to this template).
# Copy it outside the repository, replace every <address> and delete the lines you do not use.
# Compile it into the game, then build the game again (README.md, Building):
#   gyroship-tools recompile <exefs> --out generated/game --probes <this file>
# or the launcher's Probe list field, then its two Setup steps. Any change means both again.
#
# Every address comes from your own copy of the game and holds for one build only
# (gyroship-tools nso info <exefs>/main prints its build ID): never commit a filled copy.
# Build: <build ID>
#
# One "<address> <name>" per line: the address in hex (0x allowed here, unlike in the practice
# file), the name the rest of the line; # starts a comment anywhere. A probe runs before the
# instruction at its address, which must lie in a function the recompiler found: elsewhere it
# never runs. Ghidra shows the same addresses when the modules are imported with
# tools/ghidra/analyze_modules.sh.
#
# A practice line can only name a probe whose name starts with trace:
#   trace:<label> [<item>...] [if <register>[&0x<mask>]=0x<value>[,0x<value>...]]
# The labels below are the author's; any label works. Items and the condition only shape the
# --trace file, one line per pass: give a probe the items of its practice line without their
# names (f32@<EXPR>, not gauge=f32@<EXPR>: a probe with a bad item traces nothing) to check their
# values, for example
#   <address> trace:aw-update f32@<EXPR> u8@<EXPR>

# Each vehicle's per-frame boost update, at its first instruction (practice: boost lines).
